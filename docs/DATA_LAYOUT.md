# Data layout

## Curated BIDS input

For each subject, `scripts/preprocess/run_subject_pipeline.sh` expects:

```text
<CURATED_ROOT>/sub-XXXXX/ses-1/anat/
  sub-XXXXX_ses-1_T1w.nii.gz
  sub-XXXXX_ses-1_desc-brain_T1w.nii.gz
  sub-XXXXX_ses-1_desc-label_dseg.nii.gz
<CURATED_ROOT>/sub-XXXXX/ses-1/func/
  sub-XXXXX_ses-1_task-rest_bold.nii.gz
```

The brain-extracted T1w and segmentation label are external anatomical inputs. Their provenance must be documented by the data provider; they are not generated by this repository.

## MNI export root

The preprocessing script exports:

```text
<EXPORT_ROOT>/sub-XXXXX_ses-1_task-rest_space-MNI_desc-preproc_bold.nii.gz
<EXPORT_ROOT>/sub-XXXXX_ses-1_task-rest_space-MNI_desc-brain_mask.nii.gz
```

The BOLD file remains 4D and is not skull-stripped. The mask is 3D and is used only to restrict ROI extraction and global-signal calculations.

## ROI and HDF5 layout

The ROI extractor writes:

```text
<ROI_ROOT>/rois_<atlas>/<FILE_ID>_rois_<atlas>.1D
```

The HDF5 builder writes one `patients/<FILE_ID>/<atlas>/clip_dfc` dataset and one `start_frames` dataset per atlas. The training code uses the phenotype metadata and HDF5 feature manifest to map BIDS subject IDs to HDF5 IDs.

Do not commit ABIDE-I data, atlas binaries, `.1D` files, HDF5 files, model checkpoints, or generated predictions to the public repository.

The canonical reference run used an existing NeuroSTORM HDF5 with the basename
`abide1_nogsr_clip_level_dfc_seq20_startstride20_aal_cc400_ez_ho_dosenbach160_fullroi_cv10.hdf5`.
The public builder can reconstruct this layout from ROI `.1D` files, but the
source HDF5, its manifest, the source CV10 split directory, and upstream ROI
generation command are external inputs and must be archived separately for a
byte-level reproduction.
